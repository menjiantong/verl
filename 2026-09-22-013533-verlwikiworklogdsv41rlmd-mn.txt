● 好，从头讲清楚。结论一句话：N(0,1) 的填充让每个线性层把激活放大 71.6 
  倍，最后把 logits 顶到 σ≈71 
  的量级，超出数值链路能表示/能判读的范围。下面从公式一步步推到实测指标。

  ---

  第 1 步：一层线性层对"幅度"做了什么

  一个线性层 y = W x，W 形状 [out, fan_in]，元素 iid、方差 Var(w)；输入 x
  的每个元素 RMS = σ（即 E[x_j²] = σ²）：

  Var(y_i) = Σ_j Var(w_ij)·E[x_j²] = fan_in · Var(w) · σ²
  =>  RMS(y) = σ · √(fan_in · Var(w))

  fan_in = 5120（hidden_size，所有矩阵乘的 fan_in 都约在这个量级：5120 或
  2304）。

  - 训练好的模型：Var(w) ≈ 1/fan_in → RMS(y) = σ，每层"原样传递"幅度。
  - N(0,1) 填充：Var(w) = 1 → RMS(y) = σ · √5120 = σ · 71.6。

  即：每过一层线性层，幅度乘 71.6。这不是"权重有点大"的问题，而是——真模型里
  1/√fan_in 这个因子是被刻意放进去的（和 Xavier/He
  初始化同一个道理：让残差流停在一个 O(1) 的不动点上），N(0,1)
  恰好把它整个丢掉了。

  实测（layers.0 的真实张量，单位 RMS 输入）：

  ┌─────────────┬────────────────────┬──────────────────┬──────────┐
  │             │  gate.weight std   │ 专家 w1 输出 RMS │ 放大倍数 │
  ├─────────────┼────────────────────┼──────────────────┼──────────┤
  │ N(0,1) ckpt │ 1.0006             │ 73.20            │ 73.2×    │
  ├─────────────┼────────────────────┼──────────────────┼──────────┤
  │ scaled ckpt │ 0.01398 (=1/√5120) │ 1.02             │ 1.0×     │
  └─────────────┴────────────────────┴──────────────────┴──────────┘

  第 2 步：这个放大在网内怎么传导

  - 中间层：残差流 h ← h + block(h)，每个 block 的输出都是 ~73
    倍量级的成分。它没有一路炸到 71.6⁴，是因为有几个天然封顶：SwiGLU 被
    swiglu_limit=10 截断（model.py:845-847）、Hyper-Connections 的混合系数过
    sigmoid（有界）、MoE 是归一化的 top-6 凸组合。但残差流 RMS 已经涨到几十。
  - 路由（决定 6/384 选谁）也被放大：实测 384 个 gate logits std=73.25, 
    min=−178.8, max=+235.7（scaled 版是 std=1.01, min=−3.2, 
    max=+3.0）。路由本来该由 token 内容以 ±3 的差距决定；现在被 ±200
    的随机投影主导，任何 O(1) 的数值扰动（bf16 舍入、不同 kernel）都会让选中的 6
    个专家整体换一批。
  - 末层：logits = self.head(self.norm(h))（model.py:1269）。注意这个 self.norm
    是最终的 RMSNorm，它把残差流归一化回单位 RMS——所以中间涨到几十并不会直接传到
    logits。真正决定 logits 尺度的是 head 自己的权重尺度：

  RMS(logits) = √5120 × std(head.weight)

  ┌────────────────────┬────────────────┬──────────────────────────────────┐
  │     head 权重      │      std       │            logits RMS            │
  ├────────────────────┼────────────────┼──────────────────────────────────┤
  │ N(0,1)             │ 1.0            │ 71.6（实测 σ≈71，最大 ≈ 4.85σ ≈  │
  │                    │                │ 344）                            │
  ├────────────────────┼────────────────┼──────────────────────────────────┤
  │ scaled + head-gain │ 4/√5120 =      │ 4.0（实测 absmax 18.56 ≈         │
  │  4                 │ 0.0559         │ 4.85×4）                         │
  └────────────────────┴────────────────┴──────────────────────────────────┘

  第 3 步：σ≈71 的 logits 触发三个致命后果

  (1) softmax 变成 one-hot，采样退化。 词表 129280，最大 logit ≈ 4.85σ ≈
  344，top-1 与次高之间实测差 ~165 nats。exp(165) 是个 1e72 量级的数 → 概率全是
  0 或 1，熵实测 0.102（正常应 ~5）。没有探索、没有梯度信号可言。

  (2) exp 路径溢出 → nan/inf。 浮点（含 bf16，指数范围同 fp32）的安全上界是
  ln(3.39e38) = 88.7。logprob 内核要对未做 max 平移的 logits 取 exp，exp(336)
  直接 inf → 随后 inf/inf → nan。这正好解释 G12
  那一整片异常：rollout_probs_diff_* : nan、rollout_corr/training_ppl: 
  inf、kl/k3_kl: nan、actor/grad_norm: nan，以及"采样没取 argmax 而是返回任意
  token"（softmax 输出被污染成 NaN，采样器给不出有意义的分布）。training_log_ppl
  325.5 就是"任意 token 相对最大 logit 的 NLL"——和 344 这个最大 logit
  是同一个数。

  (3) 判据失效——这才是必须重做的真正原因。 我们生成随机权重不是为了训练出什么，
  而是把它当标尺去回答一个问题："权重同步对不对"。§4.4 的判据是：同步正确 →
  两侧对同一 token 的 logprob 只差 bf16
  噪声（~1e-2）；同步错位（专家错绑/布局没回退）→ O(1)~O(10)
  的落差。这个判据要求标尺满足三件事，N(0,1) 一条都不满足：

  ┌──────────────────────────────┬──────────────────────────────────────────┐
  │             要求             │          N(0,1) ckpt 的实际情况          │
  ├──────────────────────────────┼──────────────────────────────────────────┤
  │ 数值链路在范围内，能出数     │ ✗ exp(336) → nan/inf                     │
  ├──────────────────────────────┼──────────────────────────────────────────┤
  │ 基线 logprob 是              │ ✗ 基线 325 nats，1~10 的落差被完全淹没   │
  │ O(1)，落差才看得见           │                                          │
  ├──────────────────────────────┼──────────────────────────────────────────┤
  │ 对数值噪声不敏感、可复现     │ ✗ 路由 logits                            │
  │                              │ σ=73，选中的专家会因舍入而整体翻转       │
  └──────────────────────────────┴──────────────────────────────────────────┘

  第 3 条尤其隐蔽：即使不溢出，也不可用。因为"同步错了"和"噪声让路由翻了"这两种
  情况给出的都是大幅 logprob 差异，无法区分。

  第 4 步：--init scaled 就是逐项把上面这些补回来

  make_random_ckpt_dsv41_4layers.py:83-104：

  参数类别: 矩阵（attn/mlp/expert/gate/head）
  randn 模式: N(0,1)
  scaled 模式: N(0, 1/√fan_in)
  为什么: 每层保 RMS，不掉进 71× 放大
  ────────────────────────────────────────
  参数类别: RMSNorm 增益
  randn 模式: N(0,1)（实测 std≈0.58~1.0）
  scaled 模式: 恒等于 1
  为什么: 它是乘性系数，语义上初值必须是
  1；随机值等于给每个通道一个随机音量+随机翻号
  ────────────────────────────────────────
  参数类别: *.bias / attn_sink / HC base|scale
  randn 模式: N(0,1)
  scaled 模式: 0
  为什么: 这些量的"中性值"就是 0（sink 加在注意力 logits 上；HC 过
  sigmoid(mix·scale+base)）；填随机值是给路由/注意力注入固定随机偏置
  ────────────────────────────────────────
  参数类别: head.weight
  randn 模式: 同其他
  scaled 模式: 额外 ×--head-gain=4
  为什么: logits ~ N(0,4)：采样不退化（熵≈5）、exp
  安全（e^19.4=2.7e8）、又足够"尖锐"（top-1 概率≈0.4，接近真实模型）

  由此得到 5 个结构性结论（比绝对值更重要）：

  - F1 方向一致 → 不是对称舍入噪声。 bf16
    数值噪声应该是零均值、序列间符号随机；而 log_ppl_diff_min > 0，128
    条序列全部是"训练侧 logprob 更低"。这说明存在系统性偏移，不是噪声底。
  - F2 重尾 → 存在离散跳变。 diff_max/mean ≈ 
    40，说明除了一个连续小偏移，还有少量 token
    出现大跳变——这是选择类事件（专家选择、稀疏索引选择）翻转的特征。
  - F3 序列级累积。 chi2_seq 被钳在 −1（Σ log ρ ≈ 128×0.1 = −12.8 <

  - F5 两侧计算"模式"根本不同。 rollout 侧 logprob 来自 decode（KV cache + SFA

  三、方案（分 5 步，每步都有判据；按"先排除最大分支、成本最低"排序）

  Step 0｜per-token 落盘，把现象从"标量"变成"曲线"（改 ~20 行 + 跑 1 步）

  在 verl/utils/debug/metrics.py::calculate_debug_metrics 旁加一个开关，把
  (seq_idx, token_pos, rollout_logprob, actor_logprob, diff) 落成 npz。判据：
  - diff 在 response 第 1 个 token 明显不同 → 指向 prefill vs decode（F5/候选
    9）；
  - diff 随绝对位置/序列长度单调增长 → 指向窗口/压缩/索引（候选 3/4/5）；
  - 符号分布 + |diff| 分位（p50/p99/max）→ 区分"连续偏移"（候选
    2/6）与"离散跳变"（候选 1/4/7）。

  Step 1｜权重级终判：引擎侧 checksum（与 Step 0 同一次运行）

  给引擎加只读 RPC：对指名参数算 checksum/absmax，与训练侧同名参数逐一比对（覆盖
  embed/head 的 TP 分片、MoE 布局回退双向幂等、local-expert
  配对）。判据：全部一致 → 后续全部聚焦前向数值；任一不一致 →
  直接定位，不用再做后面的实验。这一步是 worklog §4.4
  早就写好的"若日后判读为同步有问题"分支，现在正好该做。

  Step 2｜teacher-forcing 的 prefill-to-prefill logits 对比（脚本级，不需 
  RL，最省）

  把整段 prompt+response 当作 prompt 喂给 vLLM 并取 prompt_logprobs（一次 
  prefill 算完所有位置），同时训练侧用 check_dsv41_fsdp_turbo_build.py
  的路径对同一份 input_ids 前向、dump
  logits。这样得到"同一模式、同一输入"的逐位置对比，把 decode 路径和 engine
  差异彻底分开。判据：prefill-vs-prefill 的 |Δlog p| 若 ≪ 0.10 → 主因在 decode
  路径（候选 9）；若仍在 0.10 量级 → 主因在共享的语义/数值差异，进 Step 3。

  Step 3｜模块二分（用 Step 2 的 harness，一次只留一个变量）

  按顺序做，每一步都能独立定案：
  1. embed+head 单算（跳过所有 layer）→ 分离 head GEMM / TP 分片；
  2. 逐层 hidden 对比（两侧 dump 同名张量）→ 找到第一层出现显著差异的位置；
  3. 注意力子路径：把 index_topk/candidate 关掉、窗口放开到全覆盖、单独打印
     compressed 可见位置集合与池化结果 → 验证候选 3/4/5；
  4. MoE 子路径：两侧 dump 每 token 的 top-6 expert id（直接比，是否翻转）+
     专家输出累加 dtype + swiglu 截断是否两侧生效 → 验证候选 1/2/7（这是 F4
     的头号嫌疑）；
  5. HC：sinkhorn 迭代次数与精度对齐 → 候选 6。

  Step 4｜判读与两种收尾（先定门槛，再看结果）

  建议门槛：prefill-vs-prefill 的 |Δlog p| mean < 1e-3、p99 < 1e-2（纯 dtype
  噪声）；decode 路径 mean < 0.02。当前 0.10 明显超标。
  - 收尾 (a)：定位到可修的语义差异（窗口边界、partial group
    可见性、截断缺失、dtype 提升）→ 修 + 用同一套 dump 复验；
  - 收尾 (b)：定位到不可消除的 kernel 近似（SFA 融合算子的稀疏选择无法与 eager
    逐位对齐）→ 把 RL 的修正真正打开：现在 rollout_correction 里 rollout_is: 
    None、rollout_rs: None，只有 metrics 在算、没有实际纠偏；打开 IS/RS + 设 KL
    阈值告警，而不是继续追数值。

  Step 3.5（并行、低成本）｜真实权重到位后的基线复测

  现在所有结论都在随机权重上。真实权重是 fp8 专家 + 
  quantization_config，反量化路径会引入第三类差异（推理 fp8 vs 训练反量化
  bf16），KL 里会再叠一层。所以顺序是：先在小权重上定位（Step 0–3）→ 再用同一套 
  dump 在真实权重上复测，否则两边的差异混在一起分不开。

      373 +### 9.5 解读                                                  
      374 +                                                              
      375 +1. **两个栈在"给定相同模块输入"时的固有数值差是同一量级**：lay

          +s，即剩余 HC/RMSNorm/head/embedding 的数值地板）。

          +稀释。                                                        
      378 +3. **误差是逐层累积的**：只对齐最后一层（`3.attn` σ 无变化、`3

      382 +### 9.6 方法上的 caveat（必须记住）                           
      383 +                                                              
      384 +- **第 0 层的嫁接是"干净"的**（输入一致：embed、attn_norm 的 r
