● 这个指标我在真实权重 dump 上离线复算了一遍，结论很明确：0.975 是这个 fixture 
  的正常量级，不是同步有问题。分三层解释。

  1. 先看它到底算什么（verl/utils/debug/metrics.py:143-166）

  actor_probs   = torch.exp(actor_old_log_probs)      # 训练侧重算
  rollout_probs = torch.exp(rollout_old_log_probs)    # 引擎生成时记录
  pearson_corrcoef = pearson_correlation_coefficient(actor_probs, rollout_probs,
  response_mask_bool)
  rollout_probs_diff = |actor_probs - rollout_probs|  # → diff_mean 0.0108 / max
  0.382

  关键：它是概率域的相关系数（不是 log 域），而且 diff_* 是
  |Δp|。概率域意味着差异按绝对值计入 → 指标几乎由高概率 token 决定；log
  域的同一份差异（log_ppl_abs_diff 0.088 nats/ token）在高概率 token 上被放大成
  |Δp| 0.01–0.38，在低概率 token 上则微不足道。

  2. 为什么两套栈算同一批权重还会有差

  1. 内核差：引擎是逐 token decode + paged KV（动态拼批），训练侧是一次 padded
     forward；RMSNorm/attention/MoE 的 bf16 累加顺序不同 → 每模块 ~0.5% ≈ bf16 1
     ULP（这是既有结论，已逐模块测过）。
  2. MoE 离散放大（主因）：这点点输入差会让部分 token-层的 top-6 
     专家集合翻转，翻转 token 的 logp 直接跳 O(1) nats——实测 97% 的平方误差落在
     ~5% 的翻转 token 上。所以分布是重尾：中位数 token 几乎一样，少数 token
     差很多。
  3. 这一轮的样本还特别"脆"：scaled32 是随机权重（head-gain
     4），路由翻转的后果比训练过的权重严重得多；而且这一步只有 4 prompt × n=2 ×
     64 token ≈ 512 个 response token，重尾 + 小样本 → 单次估计波动大。

  3. 实测对照（刚用昨天真实权重 dump 离线算的，CPU）

  | 数据 | log 域 Δlogp | 概率域 pearson（RL 同款） | |Δp| |
  |---|---|---|---|
  | 真实 4 层切片，baseline（199 token） | std 0.0967 / max 0.962 / argmax 0.950
  | 1.0000 | mean 2e-5 / max 0.003 |
  | 真实 4 层切片，输入全钉死 | std 0.0202 / max 0.069 | 1.0000 | mean 2e-5 |
  | scaled32 冒烟（你问的这行） | ~0.09 量级 | 0.9753 | mean 0.011 / max 0.382 |

  也就是说：同一个量级的 log 域差异，在真实切片上算出 1.0000，在随机权重 fixture
  上算出 0.975 ——
