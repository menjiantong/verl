## 10. `load_format=dummy` 会影响寻推一致性吗（2026-10-22）

结论：**对这个 noengram、非 LoRA 的 run，理论上不会**；代码和现有日志都不支持“dummy 更好”。上次 W2 用 dummy、这次用 auto 的差异是节点/轨迹混淆，不能直接归因于 load_format。

### 10.1 代码路径

1. **第一次 rollout 之前已经强制同步一次全量权重**：
   `verl/trainer/ppo/ray_trainer.py:1428-1430`

   ```python
   # load checkpoint and update weights before doing anything
   self._load_checkpoint()
   self.checkpoint_manager.update_weights(self.global_steps)
   ```

   之后才进入训练循环。因此 dummy 的随机初始权重在第一次生成前就被 actor 的 checkpoint 权重覆盖。

2. **非 LoRA 同步的是完整 `state_dict()`**：
   `verl/workers/engine/fsdp/transformer_impl.py:1049-1050`

   ```python
   else:
       params = self.module.state_dict()
   ```

   vision/aligner 是普通 parameter，仍在 `state_dict()` 里；`fsdp_turbo_dsv41_impl.py:1002-1008` 的注释也明确写 "The weight sync still exports them"。

3. **`base_sync_done`/`load_format` 只影响 LoRA 分支**：
   `verl/workers/engine_workers.py:673` 设置 `base_sync_done = "dummy" not in load_format`，但只在 `peft_config is not None` 时使用（`:790-806`）。本 run 没有 LoRA，每步都走完整 `per_tensor_param` 同步。

4. **dummy loader 不随机化 non-persistent buffers**：
   `vllm/model_executor/model_loader/dummy_loader.py:45-48` 明确排除 `_non_persistent_buffers_set`，与 `state_dict()` 的行为一致；这些 buffer 不是从 checkpoint 来的，auto 也不会覆盖它们，两边初始化路径相同。

5. **本 checkpoint 没有 Engram**：`noengram/config.json` 的 `engram_layer_ids: []`；dummy 跳过 Engram rotation 的风险不存在。

### 10.2 同步 payload 证据

PREV（dummy）和 CUR（auto）的 `SYNC-PROFILE`：

```text
sender:   1664 tensors, 26.19 GiB, 52 buckets
receiver: 54 buckets, 1664 tensors, load ~8.7-8.8 s
```

两边完全一致；如果 dummy 漏掉 vision/某些参数，tensor 数或 GiB 应该不同。step1 的 diff 也支持这一点：PREV 0.008138，CUR 0.007824，auto 略好而不是更差。

### 10.3 为什么仍可能有差异（caveat）

- 如果第一次同步不完整，或某个 **non-persistent buffer** 不在 `state_dict()` 中且 dummy 的默认值与 auto 不同，dummy 可能影响 rollout；当前代码/日志没有看到这种迹象。
- 如果 checkpoint 有 Engram，dummy 会跳过 `engram_rotation` 等非持久状态；本 run 不适用。
- 节点/轨迹混淆：PREV 在 21 段、CUR 在 25 段，采样和 advantage 不同；step2 之后的 diff 差异发生在 actor update 之后，load_format 在这条路径上没有作用点。

### 10.4 如何验证

- A：`load_format=auto`（当前）
