## 0. 结论摘要（先看这里）

1. **输入逐位一致时，两侧模块自身仍然差 ~0.5%，而且与专家数无关**（scaled32 与 scaled/384 专家几乎一模一样）：

   | 模块 | 输入一致时的剩余 rel_err |
   |---|---|
   | attention（4 层） | **0.0050 – 0.0057** |
   | MoE / ffn（4 层） | **0.0054 – 0.0055** |

   其中**第 0 层注意力的输入本来就是逐位相同的**（"种子"：embed → attn_norm 这一段两侧 `torch.equal == True`，rel_err 精确为 0），它那 0.57% 是**纯核差**（输入保证是逐位注入的，见 §1.2）。

2. **端到端噪声的主体不是这 0.5%，而是它被 MoE 的"离散路由翻转"放大出来的**：
   - 第 0 层 MoE：输入只差 **0.60%**，输出差 **5.2–6.5%**（len64：6.44/6.45%，即 **10.7×**；len200：5.19/5.87%，即 8.7–9.8×）——但把输入钉死后只剩 **0.54%**。
   - 逐 token 分解：**误差能量的 92–98% 落在"top-6 专家集合发生变化"的那部分 token 上**。第 0 层 len=64 时只有 3/64 个 token（4.7%）翻转，它们贡献了 **97.3%** 的平方误差；这些 token 的逐 token 相对误差 0.30，未翻转的只有 0.011。
   - 翻转率随深度与专家数增长：len=200 第 3 层 384 专家有 **85/200（42.5%）** token 翻转（32 专家时 46/200），误差能量占比仍 95%。

3. **把所有 attn/ffn 模块的输入都换成引擎侧记录值后**（`in.all`）：

   | 配置 | baseline σ(Δlogp) | **in.all σ** | 改善 | model.norm rel_err |
   |---|---|---|---|---|
   | scaled32 / len64 | 0.3181 | **0.0335** | 9.5× | 0.1434 → **0.0070** |
   | scaled32 / len200 | 0.5596 | **0.0298** | 18.8× | 0.1294 → **0.0070** |
   | scaled(384) / len64 | 1.0786 | **0.0310** | 34.8× | 0.2283 → **0.0070** |
   | scaled(384) / len200 | 0.7062 | **0.0311** | 22.7× | 0.1826 → **0.0070** |

   **四个配置的残余几乎相同（0.030–0.034 nats / 0.70% 隐状态）** → 存在一个**与专家数无关的"输入一致地板"**：它就是各模块核差（0.5%）在地板算子（HC/RMSNorm/head）上传播的结果。

4. **一句话**：训推差距 = **核差（每模块 ~0.5%，种子）× MoE 路由敏感（每层 ~10×，放大器）的逐层累积**。专家数只改变**放大器的增益**（同输入差下 384 专家的翻转率约为 32 专家的 2×），不改变核差本身。这定量解释了线上"32 专家 kl 0.11 → 384 专家 kl 0.38"：**不是误差源变大了，而是放大器变强了**。

5. **模块级没有 bug**（三条独立证据 + "0.5% ≈ bf16 的 1 ULP"论证，见 §5.1）；且**默认配置下这 0.5 nats 不进入 PG ratio**（`old_log_probs` 由训练侧重算，我们脚本没开 `rollout_correction`，见 §5.2）——它影响的是 off-policy 程度与**监控指标**（后者已被内核差饱和，不能再当"同步是否健康"用）。
6. **下一步**（详见 §5.3）：**先用真实 fp8 权重复跑本套 harness**（随机权重 + `head-gain 4` 把当前所有绝对值都放大了），再决定是"只换健康指标"还是"上 TIS/尾部纠正"；若要继续对齐内核，判据要改成**模块级的种子数量级削减**（用 `in.all.attn`/`in.all.ffn` 直接量，而不是端到端 σ）。

## 1. 方法与实现

### 1.1 与 §9 输出嫁接的区别

| | §9 输出嫁接（graft output） | **本轮 输入打桩（graft input）** |
|---|---|---|
| 注入点 | 模块**输出**（forward hook 返回引擎张量） | 模块**输入**（forward pre-hook 替换 `args[0]`） |
| 回答的问题 | "这个模块完美了，下游还剩多少差异" | **"给定同一个输入，这个模块自己还差多少"** |
| 混合态问题 | 层 ≥1 是混合态（引擎输出是在引擎输入上算的） | **无**：注入后模块的输入与引擎逐位相同 |
| 代价 | 抹掉了被嫁接模块自身的误差 | 保留模块自身误差（这正是要测的量） |

### 1.2 引擎侧输入从哪来（**不需要重跑引擎 dump**）

| 训练侧模块 | 引擎侧输入来源（已有 dump 键） |
|---|---|
| `model.layers.{i}.attn` | `language_model.model.layers.{i}.input_layernorm`（模块输出） |
| `model.layers.{i}.ffn`（MoE） | `DeepseekV41DecoderLayer.rms_norm_cast@layer{i}[0]` |

依据（`vllm_ascend/models/deepseek_v41/model.py::DeepseekV41DecoderLayer.forward`）：

```python
x = self.input_layernorm(x)
x = self.self_attn(positions, x, llama_4_scaling)
...
x, ffn_post, ffn_comb, ffn_pre = self.hc_pre(hidden_states, self.hc_ffn_fn, ..., attn_pre)
x, x_fp32 = self.rms_norm_cast(x)
x = self.mlp(x, input_ids=..., hidden_states_fp32=x_fp32, ...)
```

已核对两件事，它们决定"逐位一致"这句话是否成立：

1. `rms_norm_cast` 的两个返回值在 dump 里**逐位相等**（`[0].bfloat16() == [1].bfloat16()` 且 `[0] == [1]` 精确相等，`rel diff = 0`）→ 引擎的 `hidden_states_fp32`（MoE 路由输入）就是 `[0]` 的 fp32 上转，**注入 `[0]` 一个张量即同时覆盖 GEMM 输入与路由输入**，不存在"只对齐了一半输入"的漏洞。
2. 所有引擎侧输入张量都是 **bf16 可精确表示**的（`x.bfloat16().float() == x` 对全部元素成立）→ 把 dump 的 fp32 值回铸成 bf16 注入训练侧，是**逐位**注入，不是"近似一致"。
3. 交叉验证：`baseline` 变体记录的"自然输入"里，**第 0 层注意力的输入与引擎 `input_layernorm` 输出 `torch.equal == True`（rel = 0.00e+00）**——即 embed → 第 0 层 attn 前的整段路径两侧**逐位相同**。

### 1.3 实现要点（`probe_module_inputs.py`）

1. 每个目标模块注册**两个 pre-hook（注册顺序即执行顺序）**：① 记录"自然输入"（替换前的值，即"输入差本来有多大"）→ ② 替换为引擎张量（`.to(device, dtype).reshape(args[0].shape)`，保留 `inputs[1:]`）。
2. 变体语法：`baseline` / `in.all.ffn` / `in.all.attn` / `in.all`（两者）/ `in.<层>.<模块>`。
3. 断言"替换钩子恰好触发一次"，否则报错退出；变体字符串在**加载 checkpoint 之前**就先校验（省掉一次 2 分钟的白跑）。
4. **保真性控制**：`baseline` 变体（只记录、不替换）复现了历史 dump 的全部数字（`0.attn=0.0057 / 0.ffn=0.0644 / 1.attn=0.0445 / … / model.norm=0.1434`，σ=0.3181；len200：`0.1294 / 0.5596`）→ 钩子不扰动前向，跨运行可比。

### 2.3 输入一致时那 0.54% **长什么样**：均匀核噪声，不是离散翻转

把"输入=引擎值"那一版的 MoE 输出与引擎输出做**逐 token** 比较（`rel_err_t = ‖e_t − x_t‖/‖x_t‖`，每行 5120 维）：

| 层 | **输入一致**（`in.all.ffn`）mean / median / p99 / **max** | 自然输入（baseline）mean / median / p99 / **max** |
|---|---|---|
| 0.ffn | 0.0054 / 0.0055 / 0.0057 / **0.0058** | 0.0245 / 0.0110 / 0.3123 / **0.3171** |
| 1.ffn | 0.0054 / 0.0054 / 0.0058 / **0.0058** | 0.0738 / 0.0310 / 0.4358 / **0.4391** |
| 2.ffn | 0.0055 / 0.0055 / 0.0057 / **0.0058** | 0.1245 / 0.0466 / 0.5596 / **0.5810** |
| 3.ffn | 0.0054 / 0.0054 / 0.0057 / **0.0057** | 0.1461 / 0.0591 / 0.6668 / **0.6719** |

（64 token × 4 层 = 256 个样本）

- **输入一致时分布完全紧致**：median ≈ mean ≈ 0.0054，**max 0.0058**，没有一个 token 超过 0.05。
- **自然输入时是长尾**：median 只有 0.011–0.059，**max 0.32–0.67**——正是 §3 那些翻转 token。
- **推论（重要）：输入一致时路由不翻转**。若有一例翻转，逐 token 误差会出现 ~0.3 的离群值（翻转 token 的实测值），而 256 个样本里最大值只有 0.0058 → 翻转率 < 0.4%。也就是说训练侧 gate 与引擎 router 在相同输入上给出**相同的 top-6**（两侧都用 fp32 算 logits），这 0.54% 是**纯算术核差**（分组 GEMM 分块/累加、专家输出归约与 combine、route 权重相乘位置、shared 相加精度）。
- 因此 MoE 的误差有**两条互不相同的通道**：
  1. **算术核差 0.54%**（输入一致时依然存在，均匀、无尾）——这是 MoE 的数值地板；
  2. **离散路由翻转**（由输入差触发，把 0.6% 输入差变成 6.4% 输出差）——这是端到端差距的主体。
  只有掐掉种子（上游那 0.5% 核差）才能关掉通道 2；通道 1 只能靠换成引擎同款算子消掉（§4.2/§10 已证无"配方级"捷径）。

### 2.4 attn 在输入一致时：同样是 0.5% 的**均匀核噪声**，连稀疏选择都不翻转

同样做逐 token 比较（`in.all.attn`，输入=引擎值，逐位）：

| 配置 | 0.attn | 1.attn | 2.attn | 3.attn |
|---|---|---|---|---|
| scaled32 / len64 | 0.0058 / max 0.0062 | 0.0052 / max 0.0054 | 0.0051 / max 0.0055 | 0.0051 / max 0.0055 |
| scaled32 / len200 | 0.0057 / max 0.0063 | 0.0050 / max 0.0054 | 0.0049 / max 0.0054 | 0.0049 / max 0.0056 |
| scaled384 / len64 | 0.0058 / max 0.0062 | 0.0052 / max 0.0054 | 0.0051 / max 0.0054 | 0.0051 / max 0.0055 |
| scaled384 / len200 | 0.0057 / max 0.0062 | 0.0050 / max 0.0054 | 0.0049 / max 0.0054 | 0.0049 / max 0.0055 |

（每格：mean / max；median ≈ mean，p99 ≈ max；**8 个配置 × 4 层 × 64/200 token ≈ 5000 个样本里，逐 token 误差超过 0.05 的有 0 个**。）

- **没有离散事件**：注意力这条路上本来也有离散选择（滑窗、压缩 KV 的 `index_topk`、indexer 的 top-k），但输入一致时没有出现翻转——否则会出现 0.1–0.3 量级的离群 token。所以两侧的索引选择在相同输入下是**一致的**，残留 0.50–0.58% 全部来自核内数值（bf16 分数/概率 vs 分页融合核的高精度路径）。
- **位置剖面**：误差随位置**轻微下降**（与位置相关系数 −0.38…−0.78：位置 0 处 0.0052–0.0057，位置 ~130 处 0.0048–0.0049），**在滑窗边界（128）处没有跳变**，任何位置都不出离群 → 是平滑的核噪声，不是"某些位置选择了不同的 KV"。
- 一个自检：`0.attn` 在 baseline 里输入本来就是逐位一致的，所以它的 baseline 值与"输入一致"值**完全相等**（0.0057/0.0058）——两条独立路径给出同一个数。

### 2.5 两个模块的对照：**地板一样（~0.5%），增益完全不同**

| | attn | MoE |
|---|---|---|
| 输入一致时的自身误差 | 0.0050–0.0058，**均匀无尾**（逐 token 的 max/median ≈ 1.05–1.2） | 0.0054–0.0055，**均匀无尾**（max/median ≈ 1.05–1.1） |
| 输入有差时的行为（全张量 rel_err） | **近似"直通"（不放大）**：384/len64 层 1 输入 0.0572 → 输出 0.0661（1.2×）、层 3 输入 0.1834 → 输出 0.1821（1.0×）。逐 token 的 max/median ≈ **2.3–4.3** | **放大**：384/len64 层 0 输入 0.0060 → 输出 **0.0645（10.8×）**；逐 token 的 max/median ≈ **11–29**，**长尾集中在翻转 token** |
| 长尾的来源 | 无（连续算子，没有阈值/选择） | 离散路由选择翻转（占误差能量 92–98%） |
| 端到端影响力 | 钉死其输入只把 σ 压 1.2–1.7× | 钉死其输入把 σ 压 8.9–34.8× |

→ **两个核的"数值地板"是同一个量级（~0.5%）**，训推差距之所以由 MoE 主导，不是因为 MoE 自己更不准，而是因为它是**唯一带阈值/选择的算子**，会把任何微小的输入差**离散放大**。

### 2.6 三个可以直接读出来的事实

1. **核差与专家数无关**：`in.all.ffn`/`in.all.attn`/`in.all` 三种变体的模块输出在 32 与 384 专家下**落在同一小区间**（attn 0.0049–0.0057，MoE 0.0054–0.0055），`model.norm` 也都落在 0.0070–0.0080（两者权重不同、专家数不同，却给出同一个数）。**所以"专家数把差距放大"完全发生在输入传播路径上，不发生在两个核的内部。**
2. **baseline 的误差随专家数变大，且全部来自 MoE 行**：384 专家 len64 的 `3.ffn` 从 0.2168（32）涨到 0.3768（384），而 `3.attn` 只从 0.0865 到 0.1821（注意力行也涨是因为它的输入差被上游放大了：0.1218→0.1834）。
3. **注意力是"种子"，但自身不是放大器**：把**注意力**输入钉死（`in.all.attn`）只把 σ 压 1.2–1.7×；把 **MoE 输入**钉死立刻压 8.9–32×，且 `in.all` ≈ `in.all.ffn`（注意力输入是否钉死几乎不影响最终结果）。

## 3. 放大机制：MoE 的离散路由翻转（本轮新证据）

`summarize_probe.py` 用**训练侧自己**的两套路由做对比：`baseline`（在训练侧自然输入上选择专家）vs `in.all.ffn`（在**引擎输入**上选择专家，因为该变体把 MoE 输入钉死了）。同一模块、同一权重，输入只差 0.6%–18%。

|---|---|---|---|---|---|---|---|
| 64 | 0.ffn | 0.953 | 0.992 | 3/64 | 0.299 | 0.011 | **0.973** |

| 64 | 2.ffn | 0.766 | 0.956 | 15/64 | 0.347 | 0.056 | **0.844** |
| 64 | 3.ffn | 0.797 | 0.956 | 13/64 | 0.422 | 0.076 | **0.834** |
| 200 | 3.ffn | 0.770 | 0.955 | 46/200 | 0.387 | 0.063 | 0.949 |

**scaled（384 专家）**

| len | 层 | top-6 集合一致率 | 槽位重合 | 翻转 token | 翻转 token 的 rel_err | 未翻转的 rel_err | **翻转占误差²比例** |
|---|---|---|---|---|---|---|---|
| 64 | 0.ffn | 0.953 | 0.992 | 3/64 | 0.293 | 0.011 | **0.972** |

| 64 | 2.ffn | **0.500** | 0.883 | **32/64** | 0.400 | 0.076 | **0.948** |
| 64 | 3.ffn | **0.406** | 0.852 | **38/64** | 0.450 | 0.132 | **0.921** |
| 200 | 1.ffn | 0.840 | 0.966 | 32/200 | 0.349 | 0.022 | 0.981 |
| 200 | 2.ffn | 0.685 | 0.930 | 63/200 | 0.384 | 0.038 | 0.969 |
| 200 | 3.ffn | **0.575** | 0.898 | **85/200** | 0.418 | 0.063 | 0.949 |

**读法**：

- **误差是"少数 token 的离散事件"**：第 0 层只有 4.7% 的 token 换了专家，却贡献 **97%** 的平方误差；未翻转 token 的误差（0.011）只比核差（0.0054）大 2×。→ 6.4% 不是"每个 token 都错 6.4%"，而是"少数 token 错 30%"。
- **专家数放大的是翻转率**：同一层、**输入差几乎相同**时，384 专家翻得更多——len64 层 1：输入差 0.0555 vs 0.0584（基本相同），翻转 10/64 → **20/64**，输出误差 0.1311 → **0.1912**。这与"专家越多、top-k 越接近平局"的直觉一致，定量解释了"32 专家 kl 0.11 → 384 专家 kl 0.38"：**放大器的增益变强了，而不是核差变大了。**
  > ⚠️ 这一条是**跨 checkpoint** 比较（`scaled32` 与 `scaled` 的 router 权重是两套不同的随机矩阵），所以"翻转率翻倍"里既有"专家数"因素也有"换了一套随机权重"因素，**不能严格归因于专家数本身**；严格的对照需要同一个 checkpoint 增减专家数（未做）。§11.3-2 的"差距随专家数增长"结论有同样的混淆，本轮的贡献是为它补上了**机制**（翻转占误差能量 92–98%），而不是严格的因果对照。
- 与 §6.2 的线上尾部（`|Δ|>2 nats` 的 token 占 1.5%）同源：翻转 token 的逐 token 误差 0.3–0.45（≈ 1–3 nats 量级），就是那条尾巴。

## 5. 判断与下一步

### 5.1 判断：模块级"**没有 bug**"，但要分三层看

1. **没有 bug（三条独立证据）**：① 权重逐张量一致（§2）；② 输入相同时**连离散选择都逐 token 一致**——路由 top-6（§3）与注意力的滑窗/压缩 KV 索引（§2.4 无离群值）都不翻转；③ 残差 ~0.5% 恰好是 **bf16 的 ~1 ULP**（bf16 eps = 2⁻⁸ ≈ 0.39%，实测 0.49–0.58%）。→ 两个栈**各自都是"bf16 下正确"的实现**，差异只是舍入路径不同。
2. **"对齐内核"的天花板因此很低**：不共用同一套 kernel，就不可能把 0.5% 压到 0；训练侧换引擎核又被 §4.2（A2/A3 布局）、§10（dtype 配方无收益）堵死。
3. **但端到端差距是真实的**（σ 0.30–1.08 nats、kl 0.11/0.38），机制已在 §3 闭环。

**关键新认识：放大是"离散/混沌"的** —— 这解释了此前看着矛盾的结果：§4.1 把注意力从 bf16 概率改成 fp32（种子 0.34%→0.19%，降一半），端到端 σ 反而**升**（0.3207→0.4352）。不是"对齐无用"，而是**落点变了**：只要还落在路由决策边界的另一侧，精度提高 2× 就没有意义。
→ **目标必须是"数量级削减种子"（→ ≤0.05%）或"让离散决策一致"，而不是"把 rel_err 降低一点"。**

### 5.2 这个差距在 RL 里走哪条路（代码核实，2026-09-22）

| 位置 | 事实 |
|---|---|
| `verl/trainer/ppo/v1/trainer_base.py::_compute_old_log_prob`（约 1608–1640 行） | **默认（decoupled）分支 = `self.actor_rollout_wg.compute_log_prob(batch)` → `old_log_probs` 由训练侧重算**；只有 `rollout_corr_config["bypass_mode"]=True` 时才 `old_log_probs = rollout_log_probs`（引擎的） |
| `verl/trainer/ppo/ray_trainer.py`（1575–1579 行） | 同样的两条分支（`bypass_recomputing_logprobs` → `apply_bypass_mode`；否则 1277/1304 行 `compute_log_prob`） |
| `verl/trainer/config/algorithm.py:667` | `rollout_correction` 默认 `None` |
| 我们的启动脚本 `examples/grpo_trainer/run_deepseek_v41_grpo_fsdp_turbo_npu.sh` | **grep 不到 `rollout_correction`** → 走默认 |

**结论：默认配置下 PG ratio 的分子与分母都来自训练侧，这 0.5 nats 不进入 ratio。** 它的真实影响只有两条：
1. 采样分布 π_rollout ≠ 训练锚点 π_old 的 **off-policy 程度**（GRPO 的裁剪隐含假设两者接近）；
2. **监控指标被内核差饱和**：`rollout_corr/kl`、`rollout_actor_probs_pearson_corr` 随**专家数**与 **head-gain** 变（32 专家 0.98/0.11 → 384 专家 0.79/0.38 → 真实权重预计回到 0.01 量级），所以**不能再用它们当"同步是否健康"的指标**（详见 [worklog_dsv41_rl.md](../worklog_dsv41_rl.md) 判读标准处的修正）。真正的健康指标应是**直接量**：模块 rel_err / Δlogp σ（本 harness）或 §2 的权重指纹。

→ 由此分岔：**(a)** 认为 off-policy 可接受 → **什么代码都不用改**，只把健康指标换成直接量；**(b)** 认为需要纠正 → 开 `algorithm.rollout_correction` 的 **token 级 TIS**，阈值按 §3 的"翻转 token 承担 90%+ 误差能量"来定。

## 7. 方法上的 caveat

- **"引擎路由"是代理值**：路由对比用的是"训练侧 gate 在引擎输入上的选择"，不是引擎自己那次前向的真实选择。原因是引擎 dump 里的 router 捕获（`AscendFusedTopKRouter._compute_routing`）只有 8/25 token 的 dummy 批次，与 prefill 的 token 流不可比（这也解释了 §9.5-4 为何要"从 checkpoint 重算"）。
- **引擎侧 routed / shared 无法分离（用 dump 时别踩）**：`language_model.model.layers.{i}.mlp.experts` 看起来像"只含 routed"，实测它就是**整块 MoE 输出**（与训练侧 `ffn` 的 cos = 0.99996、norm 397.19 vs 397.17、rel_err = 0.00545 —— 与 `.mlp` 同值），因为 Ascend 融合 MoE 把 shared 也吃进去了。所以引擎 dump 里**不能**用 `.mlp.experts` 做"routed 路径"的对比；本轮也因此**没能把 0.54% 拆成 routed / shared 两部分**（要拆需在引擎侧加 hook 或改融合核）。
- **只测 prefill↔prefill**：注入的是引擎 prefill 的输入；RL 用 rollout（**decode**）产出的 logprob，decode↔prefill 是另一条通道（§3.4 / §11.3，384 专家下必须依赖 `enable_batch_invariant`）。
- **只覆盖 4 层 / 两种长度 64,200**：更长序列（压缩 KV、index_topk 全开）与更深的层数未测。
- **未测 `in.<层>.<模块>` 单层变体**：语法支持，本轮没跑（§9 已证单层输出嫁接几乎无效）。
- **"专家数 → 翻转率"是跨 checkpoint 观察，不是严格对照**（见 §3 的 ⚠️）；同理，本轮所有"32 专家 vs 384 专家"的差异都混着"两套不同的随机权重"。
- **`in.all` 的残余 σ=0.030 里，哪些属于 attn 核差、哪些属于 MoE 核差没拆**：`in.all.ffn`（0.031–0.036）与 `in.all`（0.030–0.034）几乎相同，说明把**注意力**的输入也钉死几乎没有额外收益——注意力自身的核差已经通过它写进残差流的位置被稀释，这一点与 §9.5-2 的量级解释一致，但没有单独量化。

## 8. 真实权重 4 层复跑（2026-09-22）：**结论被翻过来了**

> **完整记录**：[worklog_dsv41_real_weights_4layer.md](worklog_dsv41_real_weights_4layer.md)

用真实 DeepSeek-V4.1-Flash（bf16 与 **W8A8 量化版**都是这个 layout）切出**第 0–3 层**（384 专家，4972 张量 / 105.88 GiB），

| | 随机 scaled384（head-gain 4） | **真实 4 层** |
|---|---|---|
| baseline σ（len64 / len200） | 1.0786 / 0.7062 | 0.2417 / 0.2573 |

说明噪声主体**不是**"输入差被 MoE 放大"，而是模块内部一个**随机权重造不出来的参数级种子**：

> 在训练侧被 `prepare_deepseek_v41_model_for_fsdp` 统一转成 bf16，而引擎保持 fp32。**
> 架构本身声明它是 fp32（`Gate.__init__`，`model.py:936`），bias **只进选择不进权重**（`(scores+bias).topk`），
> 所以它的舍入是**纯离散**的：两侧喂**逐位相同**的输入时，top-6 专家集合在 **20–62%** 的 token 上不同
> （用训练侧自己记录的 top-6 反查：bf16 值命中 100%，fp32 原值只有 21–62%；引擎侧捕获用 fp32 命中 100%，logits 吻合到 1.9e-5）。

|---|---|---|---|---|---|

| 只还原 `hc_*`+`attn_sink` | 0.2467 | 0.1882 | 同上（**无变化**） | 0.0735 | 0.829 |

→ **一项参数解释了 ~9× 的钉死地板与 2.7× 的 baseline σ**；还原后真实权重的行为**回到本篇 §2/§3 的"均匀核噪声"形态**
（地板 0.0034–0.0042、model.norm 0.0056 ≈ 随机权重的 0.0054 / 0.0070）。自然输入差也随之塌缩（`3.attn in_nat` 0.0923→0.0220）。

**对 §5.1/§5.3 的修订**：
